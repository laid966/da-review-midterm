L8

数据可视化Data Visualization拓展·超出半期范围

半期范围到 L7（降维）为止，本讲属期末拓展（覆盖 p0–p70，共 71 页）。半期卷面基本不出；期末若考，几乎只考概念辨析和"给你一份数据怎么画"的简答，算法与计算题很少。复习优先级最低，但下面几张卡的术语是全课通用背景，读一遍约 20 分钟。

🎯 本节考什么

  • 会算：像素预算——屏幕 1600×1200 只有约 192 万像素，而数据是百万/十亿级，算出"每条记录分不到 1 个像素"就懂为什么必须聚合、采样或像素导向；再会算感知带宽的倍数（视觉 >100 MB/s vs 听觉约 0.1 KB/s，差约 6 个数量级）。
  • 会背：可视化的 9 条目的（p21）；按数据类型的分类（1D/2D/3D/多维/时间 + 树/图，另有结构化/非结构化/地理/时空）；参考模型三段（raw → abstract → visual form）；InfoVis / SciVis / CG / VA 四者边界；大数据 3V 与三大挑战；五类大数据可视化技术。
  • 会区分：InfoVis vs SciVis vs CG vs Visual Analysis；可视化 vs 视觉分析 vs 数据挖掘；像素导向 vs 聚合/LOD vs 扭曲 vs 去杂；采样 vs 边捆绑 vs 查询式可视化；"看见"（perception）vs "理解"（cognition）。

为什么"看"比"读"快：三条来自感知的证据

1）视觉是带宽最大的输入通道Bandwidth

p3–p5 先问"人怎么获取信息"：听、尝/闻、触、看，然后把四种通道的带宽摆在一起——视觉走电子/光信号，带宽 > 100 MB/s；听觉走声信号，只有约 0.1 KB/s；味觉/嗅觉是化学信号、触觉是物理信号，课件说它们的带宽"无法用信息论估计"。两者差约 6 个数量级。这不是修辞：同一份信息画出来 0.01 秒进脑，念出来要几分钟。所以可视化的第一性原理是把信息搬进带宽最宽的那个通道。

答题用法：问"为什么用图不用表"时，答"视觉通道带宽高 + 早期视觉并行处理"，比答"图更好看"得分高一个档次。

2）视觉思维流水线：并行在前、串行在后Visual Thinking Pipeline

p7 是讲机制的关键一页：光信号进入后，约 20 亿神经元先做并行、自动的低层视觉属性提取（color、shape 等），形成 proto-objects 与 patterns，进入视觉工作记忆并产生 GIST（整体印象）；而语言工作记忆（verbal working memory）走的是串行、目标导向的处理。图之所以高效，是因为它把"找规律"交给并行的早期视觉，而不是交给串行、容量极小的语言回路。

3）前注意视觉通道：一眼"跳出来"的属性Pre-Attentive Visual Channels

p17 标题即前注意视觉通道：有一类视觉属性不需要逐个注视、不占注意力就能被并行、瞬间编码，于是能在整幅图上"pop-out"。这就是热力图用颜色、散点用位置的理由——让读者一眼定位，而不是逐个读数字。p16 的格式塔法则（Law of Proximity：靠得近的元素会被自动归为一组）是同一机制的近亲，所以布局本身就在编码"分组"，随手排版等于随手撒谎。

课外补充：课件该页只有图，没列清单。常考的前注意通道包括颜色（色相 hue / 明度 lightness / 饱和度 saturation）、大小、朝向、形状、位置、运动、空间分组（proximity / similarity / continuity）。判据是识别时间短于约 200–250 ms 且不受元素个数影响；反过来，需要串行注视才能完成的通道（精确长度、面积比）叫"后注意"通道，不适合编码精细数值。

视觉带宽 / 听觉带宽 ≈ (100 × 10⁶ B/s) ÷ (0.1 × 10³ B/s) ≈ 10⁶ 视觉通道吞吐量约为听觉的一百万倍——"一图胜千言"的量化版本（p4–p5）。

p24 的 taxonomy 给出 1D、2D、3D、Multi-D、Temporal，再加 Tree、Graph。前五个是"数据有几个自变量/维度"，后两个是"数据之间有没有关系结构"——简答题失分常常就失在把 Tree/Graph 当成维度。树是层次（父子），图是网络（任意连边），都不是"几维"的问题。

课外补充：课件没有讲"编码通道优劣"，但简答常问。按知觉准确性从高到低大致为：位置 > 长度 > 角度/斜率 > 面积 > 体积 > 颜色明度 > 颜色色相。要读者比较精确数值就用位置/长度，不要用面积和颜色深浅。

参考模型：任何可视化都是三段转换（p23 / p60 / p67）

这张图在 L8 里出现三次（p23、p60、p67），每次都在加一层东西，所以它是最值得背的一页。核心链路：

  1. Raw Data →（data mining / table）→ Abstract Data：把原始日志、交易、传感数据整理成关系表/抽象数据。这一步是数据变换，也是数据挖掘真正插进来的位置。
  2. Abstract Data →（filtering、encoding and layout）→ Visual Form：给每个字段分配视觉通道（编码 = visual design），再摆到屏幕上（布局 = layout algorithm）。同一份数据，编码/布局不同，结论可以完全不同。
  3. Visual Form →（rendering）→ 像素：把几何与颜色真正画出来，交给图形库/GPU。
Raw Data ──data mining──▶ Abstract Data
Abstract Data ──filter + encode + layout──▶
Visual Form ──rendering──▶ 屏幕像素
p67 变体：外面再套 Analysis + Visualisation
+ Interaction 三层循环 → Visual Analysis

考点：data mining 在 raw→abstract 之间，不在最后；encoding/layout 在 abstract→visual form 之间。把编码放到渲染之后是最常见的错答。p60 还补了两行注解：Encoding = Visual Design Technique，Layout = Layout Algorithm——这正是 InfoVis 的两个核心研究点。

InfoVis / SciVis / CG / Visual Analysis：四个名词的边界（p35–p37、p66–p67）

p35 用两根轴区分 InfoVis 与 Computer Graphics：一根是真实感（realism），一根是信息（information）。p36 再用"物理数据 vs 人造/抽象数据"区分 SciVis 与 InfoVis。合起来是四块：

研究对象目标核心问题
InfoVis 信息可视化抽象数据：网络、树、文本、统计表放大认知（amplify cognition），发现模式怎么编码、怎么布局
SciVis 科学可视化物理数据：CT/MRI、流体、气象、分子让不可见的物理场可见体绘制、等值面、流线
CG 计算机图形学几何、材质、光照照片级真实感（realism）渲染方程、光照模型、纹理
VA 视觉分析图形 + 数据挖掘/ML 模型人机协同推理交互如何让人参与迭代

判据一句话：数据本身有没有物理空间位置？有 → SciVis；没有（关系、文本、层次）→ InfoVis。所以"社交网络图"虽然画在画布上，仍属 InfoVis；"CT 体绘制"哪怕交互很花哨，也属 SciVis。CG 关注"像不像真的"，InfoVis 关注"看不看得出规律"。

p37 讲趋势：传统上 SciVis 与 InfoVis 分家，现代做法是把 InfoVis + data mining + machine learning 合成 Visual Analysis。p66 一句话定性：Data Mining = computational power（算力），Visual Analysis = human intelligence（人的判断）；p67 的模型把 Analysis + Visualisation + Interaction 三件套叠上去，才叫视觉分析。代表工作：Whisper（流式信息扩散，p63）、FacetAtlas 与 SolarMap/ContexTour（大规模文本语料、多关系聚类，p64）、TargetVue（Twitter 异常用户，p68）、g-Miner（多变量图上的交互式组挖掘，p69）。

最容易被问倒的一句：视觉分析不是"可视化 + 数据挖掘"的简单叠加。关键在 interaction——用户通过缩放、筛选、下钻去改查询、改模型，形成"算—看—改"的闭环；没有交互的静态大图只是可视化。

大数据：3V 与三个硬约束（p40–p45）

p40 先给量级冲击：一天 40 亿条消息、3.4 亿条 tweet，于是"信息过载（information overload）"——问题不是没有数据，而是没法从海量数据里拿到有用信息。p43 用 3V 概括大数据：Volume（体量）、Velocity（速度）、Variety（多样性）。课外补充：很多教材还加 Veracity（真实性）、Value（价值），但课件只点名 3V，答题按 3V 写最稳。

p44 给出大数据可视化的核心矛盾，这句话值得背：把百万甚至十亿条记录塞进几百万像素——一块 1600×1200 的屏幕只有约 192 万像素。课件举的例子是 1480 万条 tweet 的信息扩散图和 5 亿用户的 Facebook 好友图。算一下就知道为什么必须上技术手段：

像素数 = 1600 × 1200 = 1,920,000 ≈ 1.92 × 10⁶ 每条记录可得像素 = 1.92 × 10⁶ / 10⁹ ≈ 0.0019 像素 十亿条记录连"一条一像素"都做不到，所以大数据可视化必须先回答"牺牲什么"：牺牲细节（聚合）、牺牲完整性（采样）、牺牲形状（扭曲），或牺牲可读性（像素导向）。

p45 把困难归结为三条，正好对应后面的五类技术：

  • Visual clutter（视觉杂乱）：重叠与交叉让图糊成一片 → 采样、重排、边捆绑、查询式可视化。
  • Performance（性能）：大数据要实时渲染 + 丰富交互 → 聚合/LOD 逐级加载、GPU 并行。
  • Limited cognition（认知有限）：信息量超过人的工作记忆 → 聚合、焦点+上下文、交互式过滤，把"一次要看的东西"降到人能处理的量级。

这三条是"为什么难"的答案，五类技术是"怎么办"的答案。简答若问"大数据可视化难在哪"，答这三条比罗列技术更能拿分。

五类大数据可视化技术（p46–p58）：每一类牺牲的东西不同

记忆抓手："像素省细节、聚合省精度、扭曲省真实、去杂省完整、GPU 省时间"。
技术做法典型代表（页）代价 / 适用
① 像素导向 Pixel-Oriented一个数据项 = 一个像素，按兴趣度或属性相似度排序后铺满屏幕Keim & Kriegel 1994/1996：1 万条 × 6 维、按兴趣度/属性相似度排序（p47–p48）；区域切分（Yang et al. 2006，p49）不丢原始记录，能看全局密度；但单点不可读，只适合概览
② 聚合 & LOD先聚合成节点建树，随缩放切换粒度：下钻 drill down 变细、上卷 roll up 变粗直方图（Pearson 1895）、热力图、InfoCube（p51）；散点图、平行坐标、星图（p52）丢个体、保趋势；粒度选错会掩盖异常
③ 扭曲 Distortion放大焦点区、压缩周边，同时保留全局上下文p53–p54（焦点+上下文类视图）形变误导长度/面积判断；适合导航，不适合精确比较
④ 去杂 Clutter Reduction抽样少画；重排减少交叉；边捆绑把平行边聚成束；查询式只画查出来的数据sampling / reordering（p55）、edge bundling（Holten & van Wijk 2009，p56，美国航线图 p10）、query engine + DB + REST API（p57）抽样丢小众模式、捆绑丢单边精度；查询式要求用户会写查询
⑤ GPU 并行把渲染/体绘制搬到 GPU 上并行p58 大规模体可视化综述（EuroVis 2014）解决性能，不解决"看不懂"

逐条说人话

像素导向最反直觉：屏幕就这么大，那就把每条记录压成一个像素，用颜色表示数值，用"怎么排"编码结构（按兴趣度排、按属性相似度排）。p47 的"order by degree of interests"就是把最该看的排到最显眼处。它不做聚合，1 万条一条不少；代价是任何单个像素都无法读数。

聚合/LOD 是"先看森林再看树"：p50 明确聚合树可自底向上（bottom-up）或自顶向下（top-down）建；p51–p52 给了一堆聚合与降维视图。注意 p52 的散点图/平行坐标/星图本质是多维降维，与 L7 降维是同一思想的不同载体。

边捆绑为什么有效：图里真正让人眼花的不是节点，而是边的交叉重叠；把走向相近的边合并成一束，既减少墨水量又突显微观结构（p56 用美国航线图演示，p10 是同一张）。查询式可视化（p57）把"画什么"交给查询引擎：database + REST API + query engine，用户先筛选再渲染，只画相关的那一小部分。

简答模板：给你一份数据，怎么设计可视化（p60–p62、p12）

p61–p62 讲工程现实：用现成工具（课件 p12 举了 Matplotlib）很容易，但开发新方法需要跨领域知识——计算机图形学、数据挖掘、人机交互、工业设计。若考"设计题"，按下面五步答，比堆技术名词有条理：

  1. 认数据类型：1D/2D/多维/时间/树/图/地理时空，先落到 p24 的某一格。
  2. 定任务：是找模式（分析）、讲故事（沟通），还是查具体值（定位）？任务不同，图不同。
  3. 选编码 + 布局：能用位置就不用面积，能用长度就不用颜色；高维做降维/平行坐标，关系数据先跑布局算法。
  4. 加交互应对大数据：概览用聚合/LOD，细节靠 drill down 与过滤，杂乱靠采样/边捆绑，查询式只画关心的子集。
  5. 验收：能不能一句话说出结论（reveal insight）？若只是"图挺好看"，回第 2 步。

⚠ 易错点 / 命题陷阱

  • 把 CG 当成 InfoVis 的子集：p35 是两根轴——CG 追真实感，InfoVis 追信息。光线追踪渲染出一张"照片"，可能一点信息量都没有。
  • 用"是否科学"区分 SciVis 和 InfoVis：判据是数据有无物理空间位置。社交网络图是科学研究对象，但仍属 InfoVis。
  • 以为"可视化 + 挖掘 = 视觉分析"：缺了 interaction，就只是"挖完再画出来"，人的判断没参与迭代（p66、p68）。
  • 把像素导向说成"缩略图/降采样"：恰恰相反，它不聚合、不丢记录，1 条 = 1 像素；代价是单点不可读。同理，LOD 的 drill down 是往细看，roll up 是往粗看，方向别弄反。
  • 把 data mining 放到参考模型最后一步：它在 raw→abstract 之间，最后一步是 rendering。课外补：前注意通道也不是越多越好，同时用颜色+大小+形状+运动编码四个量会互相干扰，强调层级时通常只用一个通道，其余保持中性。

🧠 随堂自测

Q1 归类：把下面四项分别归到 InfoVis / SciVis / CG / Visual Analysis，并各说一句理由。（a）医院 CT 的体绘制；（b）Twitter 好友关系网络图；（c）电影特效里的光线追踪渲染；（d）分析师在界面里筛选、下钻并实时改模型的异常用户排查系统。

答案：（a）SciVis——物理数据（人体密度场），用体绘制/等值面让不可见的物理场可见；（b）InfoVis——抽象的关系数据，无物理空间位置，核心是编码与布局；（c）CG——目标是真实感几何/光照/材质，不追求信息洞察；（d）Visual Analysis——图形 + 挖掘模型 + 交互，人机协同（p66–p68）。判据：先问"数据有无物理位置"，再问"有没有交互与模型参与迭代"。

Q2 计算：屏幕 2560×1440，手上有 10 亿条记录。平均每条记录能分到几个像素？若要求"每条至少 1 像素"，至少需要多少条记录以内？这对技术选型说明什么？

答案：像素数 = 2560 × 1440 = 3,686,400 ≈ 3.69 × 10⁶。10⁹ ÷ 3.69 × 10⁶ ≈ 271 条记录挤在 1 个像素里。反过来，"一条一像素"最多只能放约 369 万条记录。结论：数据量超出像素预算两个数量级以上，必须先用聚合/LOD（得到趋势）或采样（得到分布），或用像素导向把 1 条压成 1 像素但接受不可读数；实时交互则再叠 GPU/查询式过滤。这正是 p44–p45 的核心矛盾。

Q3 简答：500 万条航班记录画成"城市对-连线"图后糊成一团，说出两个病理名称和对应的两种技术，并解释各自牺牲了什么。

答案：病理是 visual clutter（重叠与交叉），加上数据量远超像素预算。技术一：边捆绑（edge bundling）——把走向相近的边合成束，减少交叉、突显主干枢纽，代价是丢失单条航线的精确走向（p56 的美国航线图正是此例）。技术二：聚合 + LOD——把城市对聚合成区域级流量或按缩放切换粒度，代价是丢失个体记录；也可用采样先画子集，代价是丢小众模式。答题要点是"技术 + 代价"成对出现。

Q4 填空：补出参考模型的三个变换及其所属步骤——Raw Data →（①）→ Abstract Data →（②）→ Visual Form →（③）→ 屏幕。

答案：① data mining / table（数据变换，数据挖掘在这里）；② filtering、encoding and layout（视觉编码 = visual design，布局 = layout algorithm）；③ rendering（渲染）。记忆：数转 → 编布 → 渲。p67 的视觉分析变体还要在这条链外面加 Analysis + Visualisation + Interaction 的循环。

记忆口诀：视觉带宽百万倍，并行在前串行后；九条目的归四组，洞察不是好看图；数据先分七类半（1D/2D/3D/多维/时间 + 树/图），树图不是维度算；模型三段数转编渲，挖掘插在第一段；三大挑战糊慢懵（clutter / performance / cognition），五招像素聚扭杂（聚合/扭曲/去杂）；比较记得 Info 与 Real，判定先看有无空间。
