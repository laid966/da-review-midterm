相似性搜索 I：Shingling、Min-Hash 与 LSHSimilarity Search I高频

对应课件 p1–p55（抽取文本 PAGE 0–54）。这一讲最容易出手算大题：Jaccard、Min-Hash 签名矩阵、1−(1−sʳ)ᵇ 三条线都能独立命题，同时是 L4（LSH 家族）和 L9（协同过滤里的 Jaccard/余弦）的地基。

🎯 本节考什么

  • 会算：k-shingle 集合（重复 shingle 只算一次）；Jaccard 相似度与 Jaccard 距离；给定置换表手算 Min-Hash 签名矩阵；用 1−(1−sʳ)ᵇ 算候选对概率、假阴性率、假阳性率；由 b、r 反推阈值 t。
  • 会背：三步流水线 Shingling → Min-Hashing → LSH 各自解决什么；Pr[h(C1)=h(C2)] = sim(C1,C2) 的 A/B/C/D 行证明；N = 100 万去重需 N(N−1)/2 ≈ 5×10¹¹ 次比较 ≈ 5 天；10 万篇文档、签名长 100 的整数只需 40MB。
  • 会区分：Jaccard 相似度（越大越像）vs Jaccard 距离（越小越像）；行置换（思想实验）vs 行哈希（one-pass 实现）；b（band 数，管召回）vs r（band 内行数，管精度）；false positive（白算一次）vs false negative（永远漏掉）。

核心概念 1：为什么需要 LSH——动机、复杂度与代价

三类真实场景（p1–p8）

图像检索：把每张图编码成一个特征向量（课件举例是 4k 维），查询图像 patch 就变成"在 embedding 空间里找最近邻"。RAG（Retrieval Augmented Generation）给 LLM 外挂知识库，动机是 LLM 的三个毛病：domain knowledge gap、factuality 问题、hallucination；工程落点就是 vector database（向量库）。所以"找相似"不是玩具问题，而是大模型时代的检索底座。

课件 p9 把它抽象成两类问题：数据点 x₁, x₂, … 是高维向量（图像 = 一长串像素颜色），给定距离函数 d，(a) 单查询：给定 q，找出所有满足 d(q, xⱼ) ≤ s 的点，朴素做法 O(N)，LSH 后是 O(1)；(b) 全对：找出所有满足 d(xᵢ, xⱼ) ≤ s 的点对，朴素做法 O(N²)，LSH 后是 O(N)。

这里的 O(1)、O(N) 都是"期望 + 近似"意义下的复杂度，不是确定性保证；代价就是下面要讲的 false negative。

文档去重：N = 100 万到底有多慢（p14）

朴素做法要对所有文档两两比相似度，对数 = N(N−1)/2，N = 10⁶ 时约 5×10¹¹ 次比较。按每秒 10⁶ 次比较、一天约 10⁵ 秒算，需要 5×10¹¹ ÷ 10⁶ = 5×10⁵ 秒 ≈ 5 天；N 涨到 10⁷，就要一年以上。另一类场景是 10B 篇文档里，给查询文档 q 快速找最相似的一篇。

这个算例是送分题：记住"对数 ≈ N²/2，时间 = 对数 ÷ 每秒比较数，秒换天除以 86400（约 10⁵）"，换任何 N 都能重算。

LSH 的定位：只砍候选集，不保证正确

LSH（Locality-Sensitive Hashing，局部敏感哈希）不是一种算法，而是一族相关技术：用多个不同的 hash 函数把 item 扔进桶，只检查"至少在一种哈希下同桶"的那些 item 对。Upside：设计得当时只有很小一部分点对被真正检查。Downside：存在 false negatives——确实相似的 item 可能因为没同桶而被永远漏掉。

所以 LSH 永远只是"筛候选"：p53 明确说，候选对还要在主内存里确认签名真的相似，可选地再回原始数据做一次精确验证。问"为什么 LSH 是近似算法"，答"false negative 不可避免，b、r 只能调概率，不能清零"。

核心概念 2：Shingling——把文档变成集合

k-shingle（k-gram）的定义

文档的 k-shingle 是文档中出现的长度为 k 的 token 序列；token 可以是字符、单词或别的东西，取决于应用。文档 D 就被表示成它全部 k-shingle 构成的集合 S(D)。为了省内存，再把每个 shingle 哈希成（比如）4 字节的整数，于是文档 = 它所有 k-shingle 哈希值的集合。

例（p19）：k=2，D1 = abcab，则 S(D1) = {ab, bc, ca}，哈希后 h(D1) = {1, 5, 7}。注意 "ab" 在 abcab 里出现两次，但集合里只算一次，5 个字符只有 3 个不同的 2-shingle——这是最容易算错的地方。

k 取多大：为什么是 8、9、10

课件说实践中常用 k = 8、9 或 10（字符级）。判断标准是"能不能把相似与不相似的文档分开"：k 太小（极端例子 k=1，字符只有 26 种），任意两篇文档的 shingle 集合几乎重合，Jaccard 都接近 1，完全没有区分度；k 太大，轻微改写就会让集合几乎不重合，近似重复也测不出来，集合还会膨胀。所以 k 是"区分度"与"鲁棒性"的折中。

必背性质：改一个词只影响距该词 k−1 距离以内的 shingle。换成一个数：一个词最多影响 k 个 k-shingle（起点可以是 i−k+1 到 i，共 k 个窗口）——考试常直接问"改一个词影响几个 shingle"，答 k。

受影响 shingle 数 = k（覆盖位置 i 的窗口起点为 i−k+1 … i） 课件原文：changing a word only affects k-shingles within distance k−1 of the word。这是"shingle 对局部改动局部敏感"的定量说法。

Shingle 集合丢了什么：单个 shingle 内部保留顺序，但集合本身无序，所以整段的语序信息基本丢失。要保留顺序就得加长 k 或用序列模型。

核心概念 3：Jaccard 相似度与 0/1 Boolean 矩阵

sim(C1, C2) = |C1 ∩ C2| / |C1 ∪ C2| d(C1, C2) = 1 − sim(C1, C2) = 1 − |C1 ∩ C2| / |C1 ∪ C2| 相似度取值 0–1，越大越像；取 1−sim 之后才是"距离"语义（0 表示同一集合）。课件 p21 的例子是交集 3、并集 8 → 3/8；另一页 p22 是交集 3、并集 6 → 1/2。两处数字不同，别背混，只备公式。

Boolean（0/1）矩阵视角

行 = shingle（元素），列 = 文档（集合），第 e 行第 s 列为 1 当且仅当元素 e 属于集合 s。两列的相似度就是它们"取值为 1 的那些行"的 Jaccard 相似度。真实矩阵极度稀疏，课件原话是"我们不真的构造这个矩阵，只是想象它存在"。

手算技巧（也是 Min-Hash 证明的骨架）：只盯两列，把所有行分成 4 类——A = (1,1)、B = (1,0)、C = (0,1)、D = (0,0)，记 a、b、c 为 A、B、C 类的行数，则 sim = a / (a+b+c)。D 类行对交集、并集都没有贡献，所以不进分母。

核心概念 4：Min-Hashing——大集合压成短签名且保相似度

定义（p24–p29）

要找一个 hash 函数 h(·)，使得 sim(C1,C2) 高时 h(C1)=h(C2) 的概率高、sim 低时概率低；也就是"签名的相似度"≈"集合的 Jaccard 相似度"。Min-Hash 的做法：随机取一个行置换 π，把矩阵的行按 π 重排，h_π(C) = 重排后第一个使列 C 取值为 1 的行号。对所有列、对 K 个随机置换各算一遍，就得到 K 行 × 列数 的签名矩阵 M；其相似度 = 两列签名在多少比例的行上相等。

存"原始行号"还是"重排后的位置"都行（p29）：只要所有列用同一套约定，保证"两列 min-hash 相等 ⇔ 置换后第一个 1 落在同一行"。答题时写清约定即可。

Pr[ h_π(C1) = h_π(C2) ] = sim(C1, C2) = |C1 ∩ C2| / |C1 ∪ C2| 整个 LSH 都建立在这个等式上：它把"集合相似度"换成"签名相同位数的比例"，于是亿万次集合求交变成几百个整数比较。

证明（必须能默写逻辑链）

设 a、b、c 是 A、B、C 三类行数，则 sim = a/(a+b+c)。按置换后的行序从上往下看，第一个"至少一列为 1"的行必然落在 A、B、C 三类里；行置换把这个"第一"均匀地分给 a+b+c 个候选行，每行概率 1/(a+b+c)。若命中的是 A 类（两列都 1），则两列 min-hash 相同；若是 B 或 C（只有一列是 1），则不同；D 类两列都 0，不可能成为任一列的 min-hash 位置。故 Pr[相等] = a/(a+b+c) = sim。（证毕）

误差随签名变长而变小：K 个位置独立同分布，每位相等的概率是 sim，所以相同位数的期望是 K·sim，标准差是 √(K·sim(1−sim))。

例：sim = 0.5、K = 100 → 期望 50 位相同，标准差 √(100×0.25) = 5，即大约 ±5 位。这就是"签名越长，估计越准"的定量版本。

行置换 vs 行哈希：one-pass 实现（p34）

真做一次行置换就要重排整个矩阵，代价不可接受。替代方案：取 K = 100 个 hash 函数 h_i，把 h_i 的取值排序看成"随机的行置换"。这样一遍扫描就能算完：

  1. 初始化所有签名槽 M(i, c) = ∞。
  2. 从上到下扫描矩阵的第 j 行；若第 j 行在第 c 列是 1，则对每个 i：若 h_i(j) < M(i, c)，就令 M(i, c) ← h_i(j)。
  3. 扫完所有行后，M(i, c) 就是第 i 个置换下第 c 列的 min-hash 值。

复杂度：每个为 1 的矩阵元素更新 K 次，稀疏矩阵里 1 的个数有限，所以是"一遍扫描 + 稀疏更新"。随机 hash 函数用 universal hashing：h_(a,b)(x) = ((a·x + b) mod p) mod N，其中 a、b 是随机整数，p 是大于 N 的素数，N 是元素（行）个数。

核心概念 5：LSH——分 band 打桶与 S 曲线

算法：b 个 band，每 band r 行（p38–p41）

把签名矩阵 M 按行切成 b 个 band、每个 band r 行（M = b·r）。对每个 band，把那一小段 r 个整数当键做一次哈希，桶要尽量多。只要两列在至少一个 band 上完全相同，就把它们当作候选对（candidate pair）送去做精确相似度验证。课件 p41 的假设是：桶足够多，所以"同桶"≈"该 band 完全相同"；这只是为分析方便，不影响算法正确性，真实桶里可以有多列。

例（p44）：10 万篇文档、签名长度 100 个整数 → 100000 × 100 × 4 字节 = 40MB；目标阈值 s = 0.8，取 b = 20、r = 5（M = b·r = 100）。

P(成为候选对 | sim = s) = 1 − (1 − sʳ)ᵇ 单 band 全相同的概率是 sʳ；b 个 band 全不相同是 (1−sʳ)ᵇ；"至少一个 band 相同"就是 1−(1−sʳ)ᵇ。这就是 S 曲线，考试必写。

S 曲线与阈值 t

曲线形状：s 很小时概率≈0，s 很大时概率≈1，中间一段陡升；b、r 越大越接近阶跃函数。阈值 t 取曲线最陡处，工程上有两种写法：解方程 1−(1−tʳ)ᵇ = t，或直接近似 t ≈ (1/b)^(1/r)。

1 − (1 − tʳ)ᵇ = t　⇒　令左边 = 1/2：(1 − tʳ)ᵇ = 1/2 ⇒ 1 − tʳ = 2^(−1/b) ≈ 1 − ln2 / b　⇒　tʳ ≈ ln2 / b ⇒ t ≈ (1/b)^(1/r)（粗近似）　或　t ≈ (0.693/b)^(1/r)（保留 ln2 更准） M = 100 取 b = 20、r = 5：两个近似分别给 0.55 和 0.51，解精确方程得 t ≈ 0.51（说明保留 ln2 的那个更准）。答题写 t ≈ (1/b)^(1/r) 即可，但要说明它是"曲线取 1/2 处（最陡处）"的近似。

假阴性 / 假阳性与参数取舍

false negative（假阴性）= 真相似（s 在阈值以上）却没进同一个桶，于是永远不会被检查，这是最致命的错误；false positive（假阳性）= 不够相似（s 在阈值以下）却成了候选对，只是白算一次精确相似度，可以接受。课件 p48 用曲线下方的两块面积分别标出 FN 和 FP。

调参直觉：M = b·r 固定时，r 变大（band 更长、更严格）→ 阈值 t 上移，FP 变少、FN 变多；b 变大（band 更多）→ t 下移，FN 变少、FP 变多。课件 p47 的原例：从 b=20、r=5 换成 10 个 band × 10 行，假阳性会降低，但假阴性会升高。

完整例题（p45–p46）：b = 20、r = 5、目标 s = 0.8

对一个相似度恰好 0.8 的文档对：单个 band 完全相同的概率 = 0.8⁵ = 0.328；20 个 band 全不相同 = (1−0.328)²⁰ = 0.00035，也就是约 1/3000 的 80% 相似对被漏掉（假阴性），我们能抓到 99.965% 的真相似对。

对一个相似度 0.3 的文档对：0.3⁵ = 0.00243，至少一个 band 相同 = 1−(1−0.00243)²⁰ = 0.0474，即约 4.74% 的"不相似对"变成候选对（假阳性），它们会在精确验证阶段被丢掉。

换一组参数感受精度：M = 50、r = 5、b = 10 时，s=0.8 → 1−(1−0.8⁵)¹⁰ = 1−0.67232¹⁰ ≈ 0.981（假阴性约 1.9%）；s=0.3 → 1−0.99757¹⁰ ≈ 0.024（假阳性约 2.4%）。同样是 50 个哈希，切法不同曲线就不同。

LSH 之后还有两步（p53）：先在主内存里确认候选对的签名真的相似；可选地再回原始数据精确验证一遍。答题时把"候选对 → 精确验证"写进流水线，别把 LSH 当成最终答案。

⚠ 易错点 / 命题陷阱

  • shingle 是集合不是多重集。abcab 的 2-shingle 是 {ab, bc, ca} 共 3 个，不是 4 个；"ab" 出现两次只算一次。同理算 Jaccard 时重复行不重复计数。
  • Jaccard 的分母是并集。不是行数 N，也不是 |C1|+|C2|（后者会把交集算两次）。三个数互相换算：|C1∪C2| = |C1| + |C2| − |C1∩C2|。
  • 相似度 ≠ 距离。Jaccard 相似度越大越像；Jaccard 距离 = 1 − 相似度，越小越像。LSH 的敏感族定义在 L4 用的是距离，两条曲线方向相反，别混。
  • 签名要"同一行"比较。h(C1) 与 h(C2) 相等指在同一次置换（同一行 i）下相等；把不同置换的数值拿来比是没有意义的。
  • b 与 r 的分工。b 是 band 数（OR 层，抬召回、压阈值），r 是每 band 行数（AND 层，抬精度、升阈值），M = b·r。写反了整道题全错。
  • 公式括号位置。是 1 − (1 − sʳ)ᵇ，不是 1 − (1 − s)ᵇʳ，也不是 (1 − sʳ)ᵇ（那是"全部 band 都不相同"的概率）。
  • LSH 不能消除假阴性。调 b、r 只移动阈值和 tradeoff；且"同桶 ≈ band 完全相同"本身是个分析假设，真实实现要再精确验证。

🧠 随堂自测

Q1 计算：D1 = abcab，D2 = bcaba。取 k = 2 和 k = 3 分别求 Jaccard 相似度与 Jaccard 距离。

答案：k=2：S(D1) = {ab, bc, ca}，S(D2) = {bc, ca, ab, ba}；交集 3、并集 4 → sim = 3/4 = 0.75，d = 0.25。

k=3：S(D1) = {abc, bca, cab}，S(D2) = {bca, cab, aba}；交集 {bca, cab} 共 2、并集 4 → sim = 2/4 = 0.5，d = 0.5。同一对文档，k 变了大相似度就变，这正是"k 影响区分度"的具体表现。

Q2 手算 Min-Hash：4 行 2 列矩阵，C1 = {1,3}，C2 = {2,3}；三个置换 π1 = 2,1,4,3、π2 = 4,1,3,2、π3 = 3,2,1,4。求签名矩阵并验证。

答案：π1：C1 看第 2 行是 0、第 1 行是 1 → h(C1)=1；C2 第 2 行就是 1 → h(C2)=2。π2：C1 第 4 行 0、第 1 行 1 → 1；C2 第 4、1 行都是 0，第 3 行 1 → 3。π3：两列第 3 行都是 1 → h(C1)=h(C2)=3。

签名相似度 = 3 行里相同 1 行 = 1/3。真实 Jaccard：C1∩C2 = {3}，C1∪C2 = {1,2,3} → 1/3 ✓。若用 100 个置换，期望相同位数 = 100 × 1/3 ≈ 33 位。

Q3 参数：b = 20、r = 5。求 s = 0.6 的候选概率并解释；若想把阈值降到约 0.5（仍保持 M = 100），b、r 该怎么调？

答案：0.6⁵ = 0.07776，1 − (1 − 0.07776)²⁰ = 1 − 0.92224²⁰ ≈ 0.802，即约 80.2% 的 60% 相似文档对会成为候选对，另外约 19.8% 被漏掉（假阴性）。

降阈值要"多切 band、少切行"：改 r = 4、b = 25（M 仍 100），t ≈ (1/25)^(1/4) = 0.04^0.25 ≈ 0.45；验算此时 s = 0.6 的概率 1 − (1 − 0.6⁴)²⁵ = 1 − 0.8704²⁵ ≈ 0.969。代价是 s 略低的文档对也更容易成为候选（假阳性上升）。

Q4 概念：若两列的四类行计数为 a = 4、b = 2、c = 2，求 Jaccard 相似度与"100 个置换下签名相同位数的期望和标准差"。

答案：sim = a/(a+b+c) = 4/8 = 0.5。签名每位相等的概率就是 sim，100 位独立同分布，所以相同位数期望 100 × 0.5 = 50，标准差 √(100 × 0.5 × 0.5) = 5。这也解释了为什么签名越长估计越稳：误差按 1/√K 缩小。

记忆口诀：洗切切（Shingling 切 k 片成集合）→ 压签名（Min-Hash，置换后第一个 1）→ 切 band 进桶；桶内 r 行全同才算同，桶间 b 个有一个同就收；收编概率 1−(1−sʳ)ᵇ，b 抬召回、r 提精度，阈值 t ≈ (1/b)^(1/r)。

相似集合问题：查询版

考点

P11

全对版与距离四公理

考点

这页是问题的第二种形式（全对版）：不再给定查询 q，而是找出所有满足 d(xi,xj)≤s 的点对 (xi,xj)。朴素方法要算 N(N−1)/2 个点对，O(N²)；LSH 声称能降到 O(N)。页面还给出一个函数要配叫「距离」必须满足的 4 条规则：d(x,x)=0（自身距离为零）；d(x,y)≥0（非负）；d(x,y)=d(y,x)（对称）；d(x,z)≤d(x,y)+d(y,z)（三角不等式）。

🎯 4 条公理可能出选择题；全对版 O(N²)→O(N)、查询版 O(N)→O(1)，成对记。

P12

LSH：多个哈希函数分桶

考点

这页引出本讲的主角 LSH（Locality-Sensitive Hashing，局部敏感哈希）。强调两点：①LSH 不是单一算法，而是一族（family）相关技术；②通用做法是用若干个不同的哈希函数，把数据项扔进桶（bucket）里。页面上的图（来自 Wikipedia）展示直觉：哈希把相似的项以高概率映到同一个桶，不相似的项映到不同桶——这与传统哈希「越均匀越好」的追求正好相反。

🎯 传统哈希怕碰撞，LSH 偏偏要让相似项碰撞——这就是「局部敏感」的含义。

P13

LSH 的工作方式与优缺点

考点

接着上一页，这页把 LSH 的逻辑补完整：用多个哈希函数把 items 扔进桶之后，只检查那些在至少一个哈希下共享同一个桶的项对（图中查询 q 与 x 就是这样一对）。Upside（好处）：设计得当的话，只有极小比例的点对需要真正计算。Downside（代价）：存在false negatives（假阴性）——真正相似的项可能碰巧没共享任何桶而被漏掉。用一点准确率换巨大速度，就是 LSH 的本质权衡。

🎯 false negative（漏掉真相似对）是 LSH 固有的；false positive 可靠后续精查剔除。

P15

动机计算：暴力法有多慢

考点

这页用数字说明为什么需要 LSH。在 N=100 万篇文档中找近重复（near-duplicate）：朴素做法要对每对文档算相似度，共 N(N−1)/2 ≈ 5×10^11 次比较；按每天 10^5 秒计算时间、每秒 10^6 次比较，需要 5 天；若 N=1000 万，要超过一年。另一个场景：100 亿（10B）篇文档的库里快速找出与查询文档 q 最相似的一篇——逐一比较根本不可行。这就是后面三步技术的动机。

🎯 记数字链条：5×10^11 对、每秒 10^6 次、每天 10^5 秒→5 天；1000 万篇→超一年。

三步法总览

🎯 三步的顺序与各自作用（转集合→压签名→找候选对）是经典框架考题。

流水线全景图

这页把三步画成完整流程图，从左到右读：Document（文档）→ 变成「文档中出现的长度为 k 的字符串集合」（shingle 集合）→ 压缩成 Signatures：短整数向量，代表原集合并反映集合间相似度 → 送入 Locality-Sensitive Hashing → 输出 Candidate pairs：那些需要真正测试相似度的签名对。关键理解：LSH 不直接给出最终答案，它只把范围从「所有对」缩小到「少数候选对」，之后还要精确计算。

第 1 步：Shingling

这页是流程图的第一格，高亮 Step 1：Shingling——把文档转换成一个集合。图中左边还是 Document，右边已经是「文档中出现的长度为 k 的字符串的集合」。为什么要转成集合？因为集合有现成的 Jaccard 相似度可以度量文档相似，而且后面的 Min-Hash 也是在集合上运作的。具体怎么切 shingle，见第 19–20 页。

P19

k-shingle 的定义

考点

这页给正式定义：文档的一个 k-shingle（又叫 k-gram）是文档中出现的任意连续 k 个 token 的序列。token 可以是字符、单词或其他单位，取决于应用；幻灯片假设 token＝字符。太长的 shingle 可以哈希压缩（比如压到 4 字节）。最终：一个文档用它所有 k-shingle 的哈希值集合来表示。你可以把 shingle 想成用长度为 k 的滑动窗口在文档上扫，扫出来的每个小片段。

🎯 文档表示成 shingle 的「集合」（去重），不是序列——顺序信息被丢掉。

P20

shingle 例子：abcab

考点

这页给了必须会手算的例子：k=2，文档 D1=abcab，滑窗切出 ab、bc、ca、ab，去重后 S(D1)={ab, bc, ca}；再把每个 shingle 哈希成整数，如 h(D1)={1,5,7}。实践中 k 常取 8、9 或 10。shingle 的两个好处：①直觉上相似的文档会共享大量 shingle；②改动一个词，只影响离该词距离 k−1 以内的 k-shingle，其余不变——所以 shingle 表示对小改动很稳健，适合检测近重复文档。

🎯 给短文档和 k，要能手写出 shingle 集合；注意去重（abcab 里 ab 出现两次只算一个）。

P21

Jaccard 相似度与距离

考点

这页定义文档变成集合后怎么量相似。设 Ci=S(Di) 是文档 Di 的 shingle 集合，Jaccard 相似度：sim(D1,D2)=|C1∩C2|/|C1∪C2|，即两集合公共元素个数除以元素总个数；Jaccard 距离：d(C1,C2)=1−sim。页面上的图给了例子：交集有 3 个元素，并集有 8 个，所以 Jaccard 相似度＝3/8（对应 Jaccard 距离＝5/8）。

🎯 相似度与距离之和为 1：算出 3/8 是相似度，题目问距离要答 5/8，最常见的坑。

P22

布尔矩阵：行shingle列文档

考点

这页引入一个有力的思维工具：把每个集合编码成 0/1（布尔）向量，拼成一个大矩阵——行＝元素（shingle），列＝集合（文档）；第 e 行第 s 列为 1 当且仅当元素 e 属于集合 s。两列的相似度就是对应集合的 Jaccard 相似度。这种矩阵通常非常稀疏（绝大多数是 0）。图中例子：C1、C2 两列同时为 1 的行有 3 行（交集＝3），至少一列为 1 的行有 6 行（并集＝6），故 sim(C1,C2)=3/6，d(C1,C2)=1−3/6=3/6。注意底部标注：我们并不真的构造这个矩阵，只是想象它存在。

🎯 交集＝两列都为 1 的行数，并集＝至少一列为 1 的行数；从矩阵读 Jaccard 是经典题型。

P23

阶段小结与下一个目标

这页承上启下：到此已完成「文档→shingle 集合→（想象中的）布尔矩阵列向量」。下一个目标：为每列计算小签名的同时找出相似的列，并要求「列的相似≈签名的相似」。两个警告（Warnings）：①比较所有列对耗时太多——那是 LSH 的活；②这类方法会产生false negatives（漏检），若不做可选的精确复核还会有 false positives（误报）。记住这两个词，第 44–46 页会定量计算它们。

第 2 步：Min-Hashing

流程图再次出现，这页高亮 Step 2：Min-Hashing——把大集合压缩成短签名，同时保持相似度。图中「文档→k 字符串集合」这步已完成（Step 1 的产物），现在要把集合再压成 Signature：短整数向量，既能代表原集合，又能反映集合之间的相似度。为什么要压？因为原集合可能有百万级元素，直接比较太贵。第 25–27 页讲这个哈希函数长什么样、为什么能保相似。

P25

哈希函数的理想性质

考点

这页说清 Min-Hashing 的设计目标：把每列（集合）C 哈希成一个很小的签名 h(C)，使 sim(C1,C2) 与签名 h(C1)、h(C2) 的「相似度」一致。具体要找哈希函数 h(·) 满足：若 sim(C1,C2) 高，则以高概率 h(C1)=h(C2)；若 sim(C1,C2) 低，则以高概率 h(C1)≠h(C2)。直觉：把文档哈希进桶，期望大多数近重复文档对会落进同一个桶——「局部敏感」由此得名。

🎯 「高相似→高概率哈希相等；低相似→高概率哈希不等」就是 LSH 哈希的定义，可能考简答。

P26

哈希函数依赖相似度度量

这页补充一个关键认识：满足上页性质的哈希函数不是万能的，它取决于你用的相似度度量——并非所有相似度度量都存在合适的哈希函数。而对 Jaccard 相似度，恰好存在一个合适的哈希函数：就是 Min-Hashing。其他相似度函数（如下讲要讲的余弦相似度、欧氏距离等）如何与 LSH 搭配，留到下一讲。所以本讲的主线始终是：Jaccard 相似度＋Min-Hash。

P27

minhash定义：置换后首个1

考点

这页给出 minhash 的正式定义。先做思想实验（并不真的执行）：用某个排列 π 把布尔矩阵的所有行随机重排。对该排列，定义 hπ(C)＝列 C 在置换后顺序中第一个取值为 1 的行号，记作 hπ(C)=min π(C)。然后取多个随机选择的排列，对每一列都算出各排列下的 minhash 值，就得到每列的一个签名。所有签名拼成签名矩阵：列仍是原来的集合，每一行对应一个排列的 minhash 值。

🎯 一句话定义：把行序随机打乱后从上往下看，第一个出现 1 的行号就是 minhash 值。

P28

签名矩阵计算示例

考点

这页是完整算例：左边是输入布尔矩阵（shingles×documents，4 列文档），右边是对它施加两个随机置换后得到的签名矩阵 M。跟着图上标注读：对置换 π2 来说，「置换的第 4 个元素（对应原第 1 行）是第一个映到 1 的」，所以 h2(3)=4——第 2 个置换作用于第 3 列，minhash 值为 4。做法归纳：先按置换重排行序，再从上往下找该列第一个 1，记下它的编号；签名矩阵每行对应一个置换、每列对应一个文档。

🎯 给置换和布尔矩阵手算签名矩阵是标准流程题，考前务必亲手算一遍。

P29

记原行号还是置换位置？

这页澄清一个常见困惑：minhash 值到底记该行在原始矩阵中的行号，还是记它在置换后顺序中的位置（第 28 页例子用了其中一种记法）？答案：无所谓（It doesn't matter）。只需前后保持一致，并保证：两列的 minhash 值相等，当且仅当它们在置换顺序下的第一个 1 落在同一行。因为后面所有计算只关心两列的值「相等不相等」，不关心值本身是几。

P30

核心定理：Pr[h相等]＝相似度

考点

这页是全讲的理论基石：随机选排列 π，则 Pr[hπ(C1)=hπ(C2)]＝sim(C1,C2)。证明思路：设 y 是在并集 C1∪C2 的所有行里、置换后顺序最靠前的那一行。从上往下扫，C1 或 C2 中第一个出现 1 的行必然是 y；两列 minhash 相等当且仅当 y 处两列同时为 1，即 y 落在交集 C1∩C2 里。由于置换随机，y 等可能是并集中任何一行，故落在交集的概率＝|C1∩C2|/|C1∪C2|＝sim(C1,C2)。右侧小图标出 y 的位置：两列中至少一列在 y 行必有 1。

🎯 公式 Pr[hπ(C1)=hπ(C2)]=sim(C1,C2) 是后续所有计算的根基，必背，可能考证明思路。

P31

证明换种讲法：A/B/C/D 四类行

考点

这页把上页证明换成更直观的数行方式。给定两列 C1、C2，把所有行按（C1 值, C2 值）分成四类：A=(1,1)、B=(1,0)、C=(0,1)、D=(0,0)，行数分别记 a、b、c、d。则 sim(C1,C2)=a/(a+b+c)——D 类行在两个集合里都不出现，不进并集。置换后从上往下找第一个 1：这一行等可能是 A、B、C 类行中的任何一行（D 类全 0 永远不会被停下）；若是 A 类则 h(C1)=h(C2)，是 B 或 C 类则不相等。所以 Pr[h 相等]=a/(a+b+c)=sim。

🎯 D 类 (0,0) 行既不影响 minhash 也不进 Jaccard——数 a、b、c 时直接跳过全 0 行。

P32

推广到多个哈希函数

考点

这页把单个哈希的结果推广到多个哈希函数（即长签名）。定义两个签名的相似度＝它们在多少个哈希函数上取值一致的比例（fraction）。由于每个哈希函数上一致的概率恰好等于 Jaccard 相似度，两个签名相似度的期望值就等于它们所代表的列（集合）的 Jaccard 相似度。而且签名越长（哈希函数越多），期望误差越小——更多独立估计取平均更稳。这就是「短签名能保持相似度」的原因。

🎯 签名相似度＝一致的哈希函数比例；期望＝Jaccard 相似度；签名越长误差越小。

P33

实例：真实相似 vs 签名相似

考点

这页用前面的例子验证「签名保相似」。表格两行：Col/Col 是原布尔矩阵列与列的真实 Jaccard 相似度，Sig/Sig 是由签名矩阵估出的相似度。数值：列对 1-3 与 2-4 的真实相似度都是 0.75，而签名相似度分别给出 0.67 和 1.00；列对 1-2 与 3-4 真实相似度为 0，签名相似度也为 0。要看出：签名相似度是真实相似度的估计，签名短时偏差可以很明显（2-4 被高估到 1.00、1-3 被低估到 0.67），但期望相等，加长签名可减小偏差。

🎯 考题可能给签名矩阵，让你算签名相似度（一致行比例）并与真实 Jaccard 对比。

P34

工程实现：行哈希单遍扫描

考点

这页解决「思想实验」的落地问题：真的把行重排哪怕一次都代价太高。技巧：行哈希——选 K=100 个哈希函数 hi，行在 hi 下哈希值的排序就等价于一个随机置换。单遍（one-pass）算法：为每列 c 和每个 hi 维护槽位 M(i,c)，全部初始化为 ∞；逐行扫描找 1，若第 j 行在列 c 上是 1，则对每个 hi：若 hi(j)<M(i,c) 就更新 M(i,c)=hi(j)。侧栏给出随机哈希函数的取法——universal hashing：ha,b(x)=((a·x+b) mod p) mod N，其中 a、b 是随机整数，p 是大于 N 的素数。

🎯 「见 1 取更小」的单遍更新等价于置换后取最小；universal hashing 公式可能考。

P35

第 3 步：LSH 找候选对

流程图第三次出现，这页高亮 Step 3：Locality-Sensitive Hashing——聚焦那些很可能来自相似文档的签名对。此时每篇文档已有短签名（Step 2 的产物），但 10 万篇文档两两比签名仍然是天文数字。LSH 的任务：快速筛出候选对（candidate pairs）——那些值得真正测试相似度的对。具体做法叫 banding（分带），见第 36–41 页。

P36

LSH 目标与候选对思想

考点

这页先说目标：找出 Jaccard 相似度至少为 s 的文档对（s 是相似度阈值，例如 s=0.8）。LSH 的一般思想：设计一个哈希函数，直接告诉我们 x 和 y 是不是候选对——所谓候选对，就是相似度必须被真正评估（精查）的元素对。对 Min-Hash 签名矩阵的具体做法：把签名矩阵 M 的各列哈希到许多桶里，凡哈希进同一个桶的文档对就是候选对。注意「候选」的含义：只是值得精查，并非已确认相似。

🎯 候选对＝进入精查的对；LSH 的输出是候选，最终相似度还要另行计算。

P37

候选对的判定标准

这页给出候选对判定标准的理想化描述：先选定相似度阈值 s（0<s<1）；若签名矩阵 M 的两列 x、y 的签名在至少比例为 s 的行上一致（即 M(i,x)=M(i,y) 对至少比例 s 的 i 成立），它们就构成候选对。依据是前面证过的性质：我们期望文档 x、y 拥有与它们签名相同的（Jaccard）相似度，所以「签名至少 s 比例一致」就是在估计「文档相似度达到 s」。直接逐对数一致比例太慢，所以才需要下面的 banding 技巧。

P38

大思想：把列多次哈希

这页提炼 LSH 的 big idea：与其逐对数列的一致比例，不如把签名矩阵 M 的列哈希若干次，并精心安排使得：只有相似的列才大概率哈希进同一个桶（with high probability）。于是「候选对」＝「落进同一桶的对」，筛候选的成本从 O(N²) 降到近似线性。图中画的哈希桶就是这个意象：不同的列被扔进桶里，相似的挤到一起。怎么做到「只有相似列才碰桶」？答案就是下一页的 banding。

P39

Banding：把签名矩阵切成带

考点

这页展示 banding 的核心操作，务必看懂这张图：把签名矩阵 M（左）横向切成 b 个 band（带），每个 band 含 r 行；右侧把一条签名（One signature）单独抽出来展开，可以看到每个 band 就是签名中连续 r 个数构成的一小段。于是长度 M 的签名被分成 b 段，满足 b×r＝M（签名矩阵总行数）。接下来的玩法：每个 band 独立拿去哈希分桶。这张图是理解后面全部概率公式的基础。

🎯 b×r＝M（签名总行数），所有调参计算都围绕这个关系。

P40

banding 算法流程

考点

这页给出 banding 算法全文：①把 M 分成 b 个 band、每 band r 行；②对每个 band，把每一列在该 band 的部分（长度 r 的向量段）哈希进一个有 k 个桶的哈希表，k 要尽可能大；③在至少 1 个 band 里哈希进同一桶的列对，就是候选对；④调节 b 和 r，使得既能抓住大多数相似对，又只带入很少的不相似对。注意每个 band 有独立的哈希表，两列只要在任意一个 band 中相撞即成为候选。

🎯 候选条件是「≥1 个 band 相同」，不是「多数 band 相同」——容易记错。

P41

banding 图示：2 和 6 是候选

这页用图巩固上一页：左边矩阵 M 已切成 b 个 r 行的 band，右边是每个 band 对应的桶。看图上标注的两个结论：第 2 列和第 6 列在某个 band 中片段相同、哈希进同一桶，所以它们很可能相同（probably identical），构成候选对；第 6 列和第 7 列在任何 band 都没相撞，所以肯定不同（surely different），直接排除、不必精查。注意措辞差别：撞桶只是「很可能相似」（仍可能误报），没撞桶则（在理想假设下）「肯定不相似」。

P42

理想化假设：同桶＝band全同

这页给出一个简化分析的假设：只要桶数 k 足够多，两列除非在某个 band 里完全相同，否则不大可能碰巧哈希进同一个桶。因此后文一律把「落进同一桶」当作「该 band 的 r 行逐一相等」来处理。幻灯片特意强调：这个假设只是为了让概率分析简单，不影响算法的正确性——实际实现里偶尔的哈希碰撞，无非是让候选对稍微多一点、多精查几次而已。

P43

参数示例：10 万文档

这页设定后面两页要计算的完整例子：签名矩阵 M 有 100,000 列（对应 10 万篇文档），每条签名长度 100、以整数存储，因此全部签名共占 40MB 内存。任务：找出相似度至少 s=0.8 的文档对。参数选择：b=20 个 band、每 band r=5 个整数（20×5=100，恰好用完整条签名）。记住这组数字：s=0.8、b=20、r=5——第 44、45 页将用它们分别算出漏检率（false negative）和误报率（false positive）。

P44

计算：0.8 相似对漏检率

考点

这页计算false negative（漏检）率，接上页 b=20、r=5：设 sim(C1,C2)=0.8，已达阈值，我们希望它们成为候选对。一个 band 的 5 行全部相同的概率＝(0.8)^5＝0.328（每行相同的概率都是 0.8，各行独立）；于是 20 个 band 全都不相同的概率＝(1−0.328)^20≈0.00035。即约 1/3000 的 80% 相似列对会被漏掉，而 99.965% 的真相似文档对都能被找到。计算模板：先算 t^r，再算 (1−t^r)^b。

🎯 两步公式：band 全同概率 t^r；完全漏检概率 (1−t^r)^b。考试常给 s、b、r 让你算漏检率。

P45

计算：0.3 相似对误报率

考点

这页计算false positive（误报）率，参数不变 b=20、r=5：设 sim(C1,C2)=0.3，低于阈值 s=0.8，希望它们一个桶都别撞。某个特定 band 完全相同的概率＝(0.3)^5＝0.00243；20 个 band 中至少 1 个相同的概率＝1−(1−0.00243)^20≈0.0474。即约 4.74% 的相似度只有 0.3 的文档对会混进候选对——它们是误报：精查后才发现相似度低于阈值，白费功夫。但 4.74% 远小于 100%，LSH 依然省下绝大部分计算。

🎯 「至少一个 band 相同」＝1−(1−t^r)^b，与上页互补；误报可被精查剔除，漏检无法挽回。

P46

调参：b 与 r 的权衡

考点

这页总结调参逻辑：你要挑三个数——Min-Hash 的个数（即 M 的行数）、band 数 b、每 band 行数 r，约束是 M=b×r，目标是平衡 false positives 与 false negatives。课件例子：若把 b=20、r=5 改成 10 个 band × 10 行，误报数会下降（连续 10 行全同更难，不相似对更难撞桶），但漏检数会上升（真相似对也更难连续 10 行全同）。直觉记忆：r 越大筛得越「严」，b 越大筛得越「宽」。

🎯 r 增大→更严：漏检 FN↑、误报 FP↓；b 增大→更宽：FN↓、FP↑。经典调参题。

P47

S 曲线：理想的阶跃形状

从这页起出现关键图：S 曲线。横轴是两集合的相似度 t＝sim(C1,C2)，纵轴是它们「共享一个桶」（成为候选对）的概率。图上先画了理想情况（阶跃线）：t 低于阈值 s 时概率为 0（No chance if t<s）；t 超过 s 时概率直接跳到 1（Probability=1 if t>s）。旁边标注「Say yes if you are below the line」是帮助理解这条理想判界线：低于线（成为候选）就判「相似」。真实曲线是光滑的 S 形，接下来几页推导它的形状与公式。

P48

S 曲线：真实的 S 形

这页先提醒已证结论：两个 minhash 值相等的概率＝相似度 t（Remember 框）。由此出发，真实的「共享桶概率」曲线画在同一个坐标系里：横轴仍是 t，纵轴是共享一个桶的概率。曲线呈 S 形——低相似度时贴近 0，高相似度时贴近 1，中间在某处陡峭上升。为什么是 S 形？因为概率公式是 1−(1−t^r)^b：t^r 把低 t 区压得更低、高 t 区推向 1，再用 b 次「至少一个」放大，形成陡升的 S 形（公式第 50 页正式推）。

P49

S 曲线上的两类错误区域

考点

这页在 S 曲线上标出两类错误，读图能力必须过关：阈值 s 把横轴分成两段。在 s 右侧（t>s，本该相似），曲线没有贴到 1，曲线上方到 1 之间的面积就是false negatives（漏检）的概率——真相似却没成为候选；在 s 左侧（t<s，本不相似），曲线没有贴到 0，曲线下方的面积就是false positives（误报）的概率——不相似却成了候选。理想阶跃曲线两块面积都为 0；实际 S 曲线只能尽量把两块同时压小，这就是调 b、r 的目标。

🎯 s 右侧曲线上方面积＝漏检 FN；s 左侧曲线下方面积＝误报 FP。可能考看图指认。

P50

S 曲线公式推导

考点

这页把 S 曲线公式一步步推出来，四行链条必须会默写：设两列 C1、C2 相似度为 t。任取一个 band（r 行）：band 内所有行都相等的概率＝t^r；某行不相等（band 不全同）的概率＝1−t^r。b 个 band 相互独立：所有 band 都不相同的概率＝(1−t^r)^b；取补得：至少 1 个 band 相同（即成为候选对）的概率＝1−(1−t^r)^b。这就是 S 曲线的方程，纵轴「共享桶概率」对横轴 t 的函数。第 44、45 页的数值计算只是往这个公式代数。

🎯 四步链条 t^r→1−t^r→(1−t^r)^b→1−(1−t^r)^b 必须能默写，计算题全从这来。

P51

概率树：从 t 到共享桶

这页把上一页的四步推导画成概率树状图，方便对照记忆：起点是相似度 t＝sim(C1,C2)；第一层分出「band 的所有行都相等」（概率 t^r）与「band 中某行不相等」（1−t^r）；再对 b 个 band 汇总：「没有任何 band 相同」对应 (1−t^r)^b，「至少一个 band 相同」对应 1−(1−t^r)^b——最后这个就是 S 曲线纵轴的值，即成为候选对（共享桶）的概率。建议对着这张图把公式复述一遍，推导就不难了。

P52

数值表：各阈值下的概率

考点

这页把 S 曲线公式代上前例参数（b=20、r=5），列出「相似度恰为 s 的对成为候选的概率」1−(1−s^r)^b 的数值表：s=0.2→0.006；0.3→0.047；0.4→0.186；0.5→0.470；0.6→0.802；0.7→0.975；0.8→0.9996。概率从 0.2 到 0.8 急剧爬升，s=0.5 附近恰好过半——S 曲线的陡升段正好落在阈值附近。这解释了 banding 为什么高效：阈值以下的对基本被挡住（0.3 只漏进 4.7%），阈值以上的对基本被抓到（0.8 抓 99.96%）。

🎯 表中 0.3→0.047 与 0.8→0.9996 正是第 44、45 页的两个数，常考「给参数算概率」。

P53

选 r、b 得到最好的 S 曲线

考点

这页讲怎么选 r 和 b 得到最好的 S 曲线，例子参数：50 个 minhash 函数，取 r=5、b=10。图中坐标系：横轴 Similarity（相似度），纵轴 Prob. sharing a bucket（共享桶概率），画出 S 形曲线并用颜色标出两块面积：黄色区域＝False Negative rate（漏检率，阈值右侧没抓到的概率质量），蓝色区域＝False Positive rate（误报率，阈值左侧不该抓却抓到的概率质量）。曲线越陡、陡升段越贴近阈值竖线，两块面积就越小——这就是调参目标。

🎯 黄＝FN、蓝＝FP，别记反；S 曲线越陡两类错误同时越小。

P54

完整流程：调参→查签名→复核

考点

这页把整套方法收拢成操作流程：①调节 M、b、r，使得几乎所有签名相似的对都进入候选，同时排除大多数签名不相似的对；②在主存中检查候选对的签名是否真的相似（这一步剔除 false positives）；③可选（Optional）：再对原始数据扫一遍，检查剩下的候选对是否真的对应相似的文档——因为签名相似不完全等于原文档相似。三步由粗到细：LSH 粗筛、签名核对、原文复核，计算量逐级下降、精度逐级上升。

🎯 精查可剔除误报 FP，但漏检 FN 无法挽回；「可选复核」针对的是签名近似≠文档近似的误差。

P55

总结：三步全靠哈希

考点

这页是全讲总结，每一步一句话：①Shingling：把文档转换成集合表示——用哈希给每个 shingle 分配一个 ID；②Min-Hashing：把大集合压缩成保持相似度的短签名——用「保相似的哈希」，其性质为 Pr[hπ(C1)=hπ(C2)]=sim(C1,C2)，并且用哈希技巧绕过生成真正的随机排列（第 34 页的行哈希）；③LSH：聚焦很可能来自相似文档的签名对——用哈希找出相似度达到阈值 s 的候选对。贯穿主线：三步都在用哈希，但目的各不相同。

🎯 总结页即考试框架：转集合（哈希编 ID）→压签名（保相似哈希）→找候选（LSH 哈希）。
