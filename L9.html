L9

推荐系统Recommendation Systems拓展·超出半期范围

半期终点是 L7，本讲属期末拓展（覆盖 p0–p96，共 97 页）。但它和 L7 直接衔接：隐因子模型就是"带缺失值的 SVD"，RMSE、正则化、SGD 全部从 SVD 长出来。半期不考；期末若把"矩阵分解的应用"当大题，这里的公式与 Netflix 数字是最现成的素材。

🎯 本节考什么

  • 会算：RMSE（含与 SSE 的换算）；基线预测 b_xi = μ + b_x + b_i；加权和/加权平均预测；item-item 的 Pearson 相似度与预测（p28–p30 有完整算例）；Netflix 10% 改善门槛 0.9514 × 0.9 = 0.8563。
  • 会背：utility matrix 与三步流程；显式 vs 隐式反馈；三大方法（content-based / collaborative filtering / latent factor）；TF-IDF；CF 的四个短板（冷启动、稀疏、first-rater、流行度偏置）；Netflix Prize 数据规模与 RMSE 阶梯；SGD 更新式。
  • 会区分：user-user vs item-item（何时更好、为什么）；Jaccard vs 余弦 vs Pearson（各自忽略了什么）；content-based vs CF（优缺点对称）；CF vs 隐因子；GD vs SGD；RMSE vs top-N 指标。

问题定义：从"货架稀缺"到"效用矩阵"（p2–p11）

为什么会需要推荐：稀缺 → 过剩

p3–p4 的逻辑链值得整段背：传统零售里货架空间是稀缺资源（电视台、影院同理），而 Web 让产品信息的分发成本接近零，于是从稀缺走向过剩（from scarcity to abundance）；选择一多，就必须有更好的过滤器（better filters），推荐引擎就是过滤器。p4 引 Chris Anderson 2004 的长尾图，p3 举了关联规则的著名案例：Into Thin Air 把 Touching the Void 推成畅销书。课外补充：长尾（long tail）指少数热门构成"头"、海量冷门构成长"尾"，推荐系统的价值在于把尾部商品也卖出去——课本只用一张图示意，未展开定义。

p5 区分两类推荐：非个性化（编辑精选、favorites、essential items、Top 10 / Most Popular / Recent Uploads）与个性化（Amazon、Netflix、YouTube，按人定制）。

效用矩阵（Utility Matrix）与三步走

p6–p7 的形式化：X = 用户集合，S = 物品集合，效用函数 u: X × S → R，其中 R 是全序集（1–5 星，或 [0,1] 实数）。把这些评分摆成矩阵就是效用矩阵 Utility Matrix：行是用户（Alice/Bob/Carol/David），列是物品（Avatar/LOTR/Matrix/Pirates），格子里是评分，空格是没评过。

p8 把整个任务拆成三步，考试按这三步组织答案最不容易漏：

  1. 收集已知评分（gathering known ratings）——怎么把矩阵填出来。
  2. 外推未知评分（extrapolating unknown ratings）——只关心高分：课件原话是"我们不关心你不喜欢什么，只关心你喜欢什么"。
  3. 评价外推方法（evaluating）——怎么衡量推荐好坏。

p9 区分反馈类型：显式（explicit）直接问用户打分，实践效果差（人们不愿被打扰），可用众包付钱标；隐式（implicit）从行为推断，例如"购买意味着高分"——但课件反问了一句关键的话：那低分怎么来？（没买/没点不等于不喜欢，这是隐式反馈的根本歧义）。

p10–p11 点出两个致命问题：矩阵稀疏（大多数人没评过大多数物品），以及冷启动（cold start）——新物品没有评分、新用户没有历史。三条解法路线：① content-based ② collaborative filtering ③ latent factor based。

Content-based：给物品建"画像"（p12–p18）

核心思想一句话：物品有 profile，推荐和用户过去高分物品相似的物品。电影的 profile = [genre, director, actors, plot, release year]；新闻的 profile = 关键词集合。p13 的流程图是"建 item profile → 建 user profile → 匹配 → 推荐"。

w_ij = TF_ij × IDF_i，IDF_i = log(N / n_i) TF_ij = 词 i 在文档 j 中的频率（需归一化，折扣长文档） 选"重要特征"的常规启发式是 TF-IDF：TF 高说明这个词在本文档里重要，IDF 高说明它在全库稀有因而有区分度；文档 = 物品，词 = 特征（p15）。

p16 给用户画像的两种做法：已评分物品画像的加权平均，或变体"按该物品评分与平均分之差加权"（喜欢得越多，权重越大）。预测用余弦相似度：给用户画像 x 与物品画像 i，估分 u(x,i) = cos(x,i) = (x·i)/(‖x‖·‖i‖)。p16 还顺手点了一句：怎么快速找离 x 最近的物品？那是 LSH 的活——与 L3 直接串起来。

content-based 的优缺点成对出现，几乎是为简答题准备的（p16–p18）。
优点对应缺点
不需要别的用户的数据 → 没有物品冷启动、没有稀疏问题找合适的特征很难（图像、电影、音乐尤甚）
能给口味独特的用户推荐新用户怎么办？没有历史就建不出 user profile
能推荐新的、冷门物品 → 没有 first-rater 问题过度专门化（overspecialization）：永远只推画像内的东西；人有多个兴趣，也无法利用别人的质量判断
可解释：能列出"是哪些内容特征导致推荐"特征工程成本高，且内容相似 ≠ 用户喜欢

协同过滤 I：user-user 与三种相似度（p20–p24）

p20–p21：CF 不建任何 profile，而是直接拿 utility matrix 的行（用户）或列（物品）当向量用，靠"和你相似的人喜欢什么"来推荐。user-user 的流程：对用户 x，找出评分最相似的 k 个用户集合 N，用 N 的评分估 x 的评分。

相似度公式问题（考点）
Jaccard|共同评分的物品| / |评过分的物品之并|完全忽略评分值：打 1 分和 5 分一样算"评过"
余弦 cosinesim(x,y) = (r_x · r_y) / (‖r_x‖ ‖r_y‖)把缺失当 0，等价于把"没评"当成"极差评"，系统性压低相似度
Pearson 相关只在双方共同评过的集合 S_xy 上算，先减各自均值再求余弦失去"评分尺度/严格程度"的信息（可解释为偏好形状相同）

p22–p23 用一组数字说明为什么要中心化，这组数字可以直接背下来当例子：直觉上我们想要 sim(A,B) > sim(A,C)；Jaccard 给出 1/5 < 2/4（顺序错），余弦给出 0.380 > 0.322（顺序对，但机制可疑——它把缺失值当 0）；减掉行均值后变成 0.092 > −0.559，差距拉开且机理正确。p23 还有一句话是选择题的常客：数据以 0 为中心时，余弦相似度就等于相关系数。

sim(x,y) = Σ_i (r_xi − r̄_x)(r_yi − r̄_y) / √(Σ_i (r_xi − r̄_x)² · Σ_i (r_yi − r̄_y)²) i 取双方共同评过的物品 S_xy；r̄_x、r̄_y 是各自平均评分。这就是"中心化后的余弦"= Pearson 相关系数（p23–p24）。

协同过滤 II：预测式、item-item、加权和与基线（p25–p33、p50–p53）

user-user：r̂_xi = Σ_{y∈N} s_xy · r_yi / Σ_{y∈N} s_xy item-item：r̂_xi = Σ_{j∈N(i;x)} s_ij · r_xj / Σ_{j∈N(i;x)} s_ij N 是 x 最相似的 k 个用户（且评过 i）；N(i;x) 是"与 i 相似且被 x 评过"的物品集合。两个式子只差"用行还是用列"，都是加权平均（p24、p26、p50）。

item-item 的完整算例（p28–p30，考试最爱考这种一步步算的）：要估用户 5 对电影 1 的评分。先算电影 1 的均值：m₁ = (1+3+5+5+4)/5 = 3.6；把第 1 行减去均值得到中心化向量 [−2.6, 0, −0.6, 0, 0, 1.4, 0, 0, 1.4, 0, 0.4, 0]；再与其他电影行做点积得 Pearson 相似度，取用户 5 评过的高相似电影：s₁,₃ = 0.41、s₁,₆ = 0.59，对应评分 r₅,₃ = 2、r₅,₆ = 3。于是

r̂₅,₁ = (0.41 × 2 + 0.59 × 3) / (0.41 + 0.59) = (0.82 + 1.77) / 1.00 = 2.6 加权平均：越相似的物品权重越大。注意分子分母都要用同一组邻居，别只除个数。

p31、p49–p52 再往前一步：直接用评分做平均不好，因为用户有"手松手紧"、物品有"本身好卖"。于是引入基线（baseline）：

b_xi = μ + b_x + b_i b_x = 用户 x 的平均评分 − μ，b_i = 物品 i 的平均评分 − μ μ 是全局平均。p49 例子：全局 3.7 星，The Sixth Sense 比平均高 0.5，Joe 比平均低 0.2 ⇒ Joe 会给 3.7 + 0.5 − 0.2 = 4 星。p82 例子：3.7 − 1 + 0.5 = 3.2，最终分数 = 3.2 + q_i · p_x。

把基线代进 CF 就是 r̂_xi = b_xi + Σ s_ij(r_xj − b_xj) / Σ s_ij——先预测一个"平庸值"，再用邻居的残差修正。p52–p53 进一步把 s_ij 换成可直接从数据学出来的权重 w_ij，并改成加权和（不再除以 Σs）：r̂_xi = Σ w_ij · r_xj。为什么？课件列了三条理由：① 相似度度量本身是"任意的"；② 成对相似度忽略了用户间的相互依赖；③ 固定权重做加权平均太受限。做法是让 w 最小化训练集 SSE，用梯度下降学出来——这一步把"启发式推荐"变成了"优化问题"。

p32 给出一句常考结论：实践中 item-item 往往比 user-user 更好，原因是"物品更简单，用户有多个口味"。

CF 的四个短板（p33）与对应解法（p34）。
短板含义解法
冷启动 Cold start系统里用户太少，找不到相似的人混合模型、用人口统计学信息
稀疏 Sparsity矩阵空得多，很难找到"评过同一批物品"的人降维 / 隐因子 / 用 LSH 找近邻
首次评分 First rater没人评过的新物品、冷门物品无法推荐加 content-based（用 item profile）
流行度偏置 Popularity bias倾向于推热门，口味独特的用户得不到好推荐混合 + 加权、降热门惩罚

注意 CF 的优点是"对任何物品都适用、不需要选特征"（p34）——与 content-based 的缺点正好互补，所以现实系统都做混合（hybrid）：实现两个以上推荐器，用线性模型合并预测；再用 content-based 补 new item、用 demographics 补 new user。

评价：RMSE、top-N 与复杂度（p36–p41）

RMSE = √( (1/N) · Σ (r̂_xi − r*_xi)² )，SSE = Σ (r̂_xi − r*_xi)² N 是比较的点数，r̂ 是预测，r* 是真值。RMSE 与 SSE 单调相关：RMSE = √(SSE/N)，所以"最小化 SSE"与"最小化 RMSE"是同一件事——这句话在 L7 的 SVD 与 L9 的隐因子之间是桥梁。

p37 的做法：把评分分成训练集与测试集，用训练集建模型、在测试集上算 RMSE。p38 还给了别的指标：Precision at top 10（前 10 个推荐里相关物品的百分比）、0/1 模型下的 coverage（系统能对多少物品/用户给出预测）、precision、ROC（假阳与假阴的权衡曲线）。p39 提醒：只盯准确率会漏掉多样性（diversity）、上下文（context）、推荐顺序（order）；而且我们只关心高评分，RMSE 可能惩罚"高分区很准、其他区很差"的方法——这是"指标选错方向"的经典论点。

p40 讲复杂度：最贵的一步是找 k 个最相似用户，O(|X|)，运行时做不起；可以预先算，但朴素预计算是 O(k · |X|)；解法是近邻搜索（LSH）、聚类、降维——又一次回到 L3/L6/L7。

p41 的结论常被引用：别为了跑花哨算法去缩减数据；简单方法 + 大数据通常最好；加数据比改算法有效（more data beats better algorithms）。课件原话："Don't try to reduce data size in an effort to make fancy algorithms work"。

隐因子模型：把 SVD 搬到带空洞的矩阵上（p58–p73）

p60–p61 用电影二维示意"区域（regional）相关性"：The Princess Diaries 与 The Lion King 靠"面向女性"，Braveheart 与 Lethal Weapon 靠"面向男性"，另一根轴是 serious–funny。这些轴就是隐因子 Latent Factor。p61 的形式化：

R ≈ Q · Pᵀ，r̂_xi = q_i · p_x R 是 users × items；Q 是 users × f（用户因子矩阵）；Pᵀ 是 f × items（物品因子矩阵）；q_i 是物品 i 的因子向量，p_x 是用户 x 的因子向量。f 是因子数，远小于用户数与物品数。 
        items                 f      factors
users [   R    ] ≈ users [ Q ] · [ Pᵀ ]
        n×m          n×f          f×m
缺失格 (x,i) 的预测：r̂_xi = q_i · p_x
对应 SVD：A = R，Q = U，Pᵀ = Σ Vᵀ

p67 明确写出对应关系：A = R、Q = U、Pᵀ = ΣVᵀ。p68 给两个关键判断：① SVD 本来就最小化重构误差（SSE），而 SSE 与 RMSE 单调相关，所以SVD 就是在最小化 RMSE；② 但有个大麻烦——SVD 的误差是对全部元素求和，缺失值会被当成 0 分，而真实矩阵有空洞。SVD 在条目缺失时根本没有定义（p69），所以只能用专门方法求 P、Q：只在已知评分上最小化误差。

p72 讲过拟合（overfitting）：想把 k（因子数）调大以捕捉更多信号，但测试集 SSE 在 k > 2 之后反而开始上升——参数越多越容易拟合噪声。p73 的对策是正则化（regularization）："数据多的地方让模型自由，数据少的地方狠狠收缩"，目标函数加 L2 惩罚：

min over P,Q： Σ_{已知 (x,i)} (r_xi − q_i · p_x)² + λ₁‖P‖² + λ₂‖Q‖² λ₁、λ₂ 是超参数（hyperparameters）；课件特别提醒：我们不关心目标函数的原始数值，只关心使目标最小的 P、Q。带基线的完整版是把 q_i·p_x 换成 μ + b_x + b_i + q_i·p_x。

优化：GD vs SGD 与更新式（p74–p79）

p74–p75：变量是 P、Q 的每个元素；P、Q 是矩阵，所以对每个元素独立更新。p56 先复习梯度下降：算出 ∇f，从某点出发，沿负梯度方向走一步 y ← y − η∇f(y)，重复到收敛。全量 GD 的问题是：算梯度很慢（要扫所有评分）。

p76–p77 的 SGD 思路：不做全量求和，只看一个评分就迈一步。GD 是 Q ← Q − η Σ_r ∇，SGD 是 Q ← Q − μ ∇(单个 r)。结果：SGD 每步便宜得多、收敛更快（虽然目标函数下降是"带噪声"的）；p77 的曲线结论是"GD 步数少但每步贵，实践中 SGD 快得多"。

ε_xi = 2 (r_xi − q_i · p_x) ← 误差项（导数） q_i ← q_i + μ₁ (ε_xi · p_x − 2λ₂ · q_i) ← 物品因子更新 p_x ← p_x + μ₂ (ε_xi · q_i − 2λ₁ · p_x) ← 用户因子更新 μ₁、μ₂ 是学习率（learning rate）。注意符号：因为是在最小化，所以沿负梯度走，等价于"加上误差方向"；正则项让它往回缩 −2λq。初始化可用 SVD（把缺失当 0 先补），再做两重循环 for until convergence { for each r_xi }（p75、p78）。

考法提示：SGD 的式子只需记结构——"误差 × 对方因子 − 正则 × 自己"；符号写反、漏掉 2 都是典型扣分点。另外记住 SGD 是增量式的：每处理一个评分就更新一次 q_i 和 p_x，所以同一轮的更新顺序也会影响结果。

Netflix Prize：数字、阶梯与故事（p44–p49、p59、p84–p96）

p44–p45 的数据必须记：训练集 1 亿条评分、48 万用户、17,770 部电影、2000–2005 共 6 年；测试集是每个用户最后几条评分（约 280 万条）；指标 RMSE；Netflix 自家系统 0.9514；2700 多支队伍；提高 10% 拿 100 万美元。held-out 设计是考点：150 万条 quiz set 分数公开上榜（leaderboard），另 150 万条 test set 只有 Netflix 知道，最终名次用 test set 定。

10% 门槛：0.9514 × (1 − 10%) = 0.9514 × 0.9 ≈ 0.8563 这就是 Grand Prize 的分数线 0.8563。会算这一条，就同时理解了"进步 10%"在 RMSE 上是绝对值降 0.0951，越往后越难。

p48 的冠军方案是多尺度建模：Global（用户/物品的总体偏差）+ Regional（因子分解，抓"区域"相关）+ Local（协同过滤，抓局部模式）三层叠加。p86–p89 讲时间动态：2004 年初平均评分突然上升，原因是 Netflix 改了界面、评分的语义变了，以及"老电影反而更好"；于是把参数改成时间的函数 r_xi = μ + b_x(t) + b_i(t) + q_i·p_x，甚至 p_x(t)（用户偏好向量逐日变化），偏置用线性趋势拟合、每 10 周一个 bin。这样到 0.876，仍然拿不到奖。p90 之后是"厨房水槽式"堆叠，最终由 Ensemble 队（多队合并模型）与 BellKor 竞争，最后 24 小时双方疯狂调参，BellKor 提前 40 分钟交、Ensemble 晚 20 分钟交，故事的最后一句是 p96 的玩笑："Submit early!"

这一讲真正的"元结论"有两条：① 多尺度/混合模型（全局偏差 + 隐因子 + 局部 CF）比任何单一模型都好；② p41 的 more data beats better algorithms——别为了炫技去砍数据。

⚠ 易错点 / 命题陷阱

  • Jaccard 与余弦的"忽略"不同：Jaccard 忽略评分值（只看评没评过），余弦把缺失当 0（等于把没评当差评）。只有 Pearson 同时处理了这两件事——先取共同评分项，再减均值。说"Jaccard 把缺失当 0"是错的。
  • baseline 不等于最终预测：b_xi = μ + b_x + b_i 只是"基线估计"，完整模型还要加交互项 q_i·p_x；把 3.7 − 1 + 0.5 = 3.2 当最终分是漏了最后一步。
  • RMSE ≠ SSE：两者单调相关但单位不同，RMSE = √(SSE/N)。答题写"最小化 SSE"没问题，写"RMSE = SSE"就错了。
  • SVD 与缺失值：标准 SVD 要求矩阵完整，缺失时没有定义；推荐里的隐因子是"只在已知评分上最小化的近似 SVD"，且不要求 P、Q 的列正交或单位长（p69）。
  • 冷启动与 first-rater 别混：cold start 是新用户/新物品没有历史；first rater 是某个物品从没人评过。content-based 能解决物品冷启动与 first-rater，但解决不了新用户冷启动。另外 k 越大不一定越好：k > 2 之后测试误差可能上升，这是过拟合，要靠正则化压。

🧠 随堂自测

Q1 计算：测试集 4 个点，(预测, 真值) 分别为 (3,4)、(4,4)、(2,3)、(5,3)。求 SSE 与 RMSE；若想"比 1.0 的基线改善 10%"，目标 RMSE 是多少？

答案：残差 = −1、0、−1、+2，平方 = 1、0、1、4，SSE = 6，N = 4，RMSE = √(6/4) = √1.5 ≈ 1.22。改善 10% ⇒ 1.0 × 0.9 = 0.90。顺带记住：RMSE = √(SSE/N)，所以"最小化 SSE"和"最小化 RMSE"等价（p68），这正是 SVD 能直接用于推荐的理由。

Q2 计算：全局平均 μ = 3.8；用户 x 的平均评分 4.4；电影 i 的平均评分 3.2；隐因子项 q_i · p_x = −0.4。求基线 b_xi 与最终预测 r̂_xi。

答案：b_x = 4.4 − 3.8 = +0.6，b_i = 3.2 − 3.8 = −0.6，基线 b_xi = 3.8 + 0.6 − 0.6 = 3.8；最终 r̂_xi = 3.8 + (−0.4) = 3.4。注意这里的 3.8 只是"这个挑剔的用户 + 这部低于平均的电影"抵消后的基线，交互项才是用户与这部电影的匹配度（p31、p82）。

Q3 计算：要给用户 x 估电影 i 的评分，可用邻居 s_i,j₁ = 0.6（x 打分 5）、s_i,j₂ = 0.3（x 打分 2）。用加权平均求预测；若改用"加权和 + 学出来的 w"，式子会变吗？

答案：r̂ = (0.6 × 5 + 0.3 × 2) / (0.6 + 0.3) = (3 + 0.6) / 0.9 = 4.0。加权和版本不再除以 Σs，而是 r̂ = Σ w_ij · r_xj，且 w_ij 是从训练集最小化 SSE 学出来的、不再等于相似度（p52–p53）；这样能建模物品间的相互依赖，也避免了"相似度度量是任意的"这一缺陷。

Q4 概念：为什么 user-user 的余弦相似度要先减掉用户均值？为什么实践中 item-item 常优于 user-user？

答案：① 因为 utility matrix 有大量缺失，余弦会把缺失当 0，等于把"没评"当成"极差评"，系统性低估相似度；减掉行均值（中心化）后，比较的是"相对于自己平均水平的偏好形状"，此时余弦恰等于 Pearson 相关系数（p23）。课件数字：中心化前 sim(A,B)=0.380 只是碰巧排对，中心化后 0.092 > −0.559 差距清晰。② 物品比人"简单"：一部电影只有一种类型/风格，而一个用户有多个口味（p32）；邻居物品的评分维度更稳定，所以 item-item 的相似度更可靠，且物品数通常远小于用户数，预计算相似度更省。

记忆口诀：矩阵稀疏三招解（内容 / 协同 / 隐因子）；内容靠画像 TF-IDF，协同靠相似度三兄弟（Jaccard 只看有无、余弦当零、Pearson 先减均值）；user-user 看人、item-item 看片，加权平均再学 w；基线三个 μ b_x b_i，交互再补 q·p；SVD 拆 R≈QPᵀ，缺失当零会失真，只在已知求最小，过拟合靠 λ 压；GD 全量算得准，SGD 一步快得飞；十个百分点 0.9514×0.9=0.8563，多尺度叠加才夺冠。
